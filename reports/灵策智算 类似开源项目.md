# 开源拼得出灵策智算，拼不出企业治理

有，而且灵策智算本身就建在开源项目之上。它官网"更新日志"页加载的官方发布记录写明，桌面端 2.0.7 版（2026-09-16）"升级 OpenClaw，两套 Harness 对齐官方新版本"，2.0.8 版"加强 OpenClaw 稳定性：改善网关启动、残留锁恢复、飞书加载……"；第二套引擎 2026-08 以"deepseek harness"之名上线，随后更名"Lynxce Harness"，并"对齐 DeepSeek Harness 0.1.3" ([官网·更新日志](https://ai.lynxce.cn/changelog.html))。"OpenClaw 加 DeepSeek Harness 双引擎、Cowork 会话层、本地 SQLite、飞书与网易云信、网易小蜜蜂（Bee）插件"这组特征，与网易有道开源的 **LobsterAI**（MIT，6,083 star，2026-10-04 仍在推送）的架构和插件清单逐项吻合 ([LobsterAI README_zh](https://raw.githubusercontent.com/netease-youdao/LobsterAI/main/README_zh.md); [package.json](https://raw.githubusercontent.com/netease-youdao/LobsterAI/main/package.json))，媒体对 LobsterAI 的定位语与灵策智算页脚的自我介绍也几乎一字不差。**在一台装有灵策智算 macOS 2.0.6 版的电脑上核对安装包，证实它就是 LobsterAI 的改名版**：包内 package.json 的名称从 lobsterai 改成了 lynxceai，保留了 LobsterAI 独有的 openclaw 配置段，插件清单的顺序和版本号也相同。官网没有声明这一点。MIT 许可证允许这种商用改名，只要求保留版权与许可声明。除此之外，截至 2026-10-05 没有任何单一开源项目覆盖灵策智算官网列出的全部能力。按本报告的 16 个功能维度打分，**OpenClaw**（MIT，约 39.1 万 star）与字节跳动的 **DeerFlow 2.0**（MIT）并列最高；企业"数字员工"一侧最接近的是面壁智能等发布的 **StaffDeck**（AGPL-3.0）；国产替补是阿里的 **QwenPaw**（Apache-2.0）和由 chatgpt-on-wechat 演进而来的 **CowAgent**（MIT），技能自进化最成熟的是 **Hermes Agent**（MIT）。直接安装 LobsterAI，或用 OpenClaw + 飞书/钉钉/微信官方插件 + MemOS + OfficeCLI 自行组装，就能获得灵策智算个人版的大部分功能；再叠加 Paperclip、Bisheng 与 Langfuse，能补上一部分企业治理。但"团队共享的 Skill/知识/上下文库 + 按角色分级权限 + 统一审计与运营看板"这一治理闭环，以及原生手机 App 派发电脑任务、企业微信侧边栏与文件库同步、跨数字员工的技能全局泛化，开源界仍无现成实现。灵策智算的安装包已公开发布（Windows 2.1.9、macOS、iOS 与 Android），官网文案仍称邀请制内测；据其更新日志，它在开源底座之上加做的是云端执行、原生手机 App、企业空间（协同文档、多维表格、CRM、企业知识库）与内容生产类应用，再加上私有化交付服务，而不是 Agent 运行时本身。选型时，许可证条款（Dify/FastGPT 限制多租户运营、NocoBase 禁做低代码 SaaS、AGPL/GPL 的源码公开义务）比 star 数更有决定性。

> 口径说明：Star、许可证与最近推送时间取自研究笔记于 2026-10-05 通过 GitHub API 读取的数据，许可证附加条款以仓库 LICENSE 文件为准。灵策智算的功能以同日抓取的官网全部页面为基线；官网的更新日志、使用文档与下载按钮由页面脚本从公开接口 api.lynxce.cn 动态加载，本报告按浏览器同样的方式读取了更新日志（82 条，桌面端最早一条为 2026-06-20 的 1.1.9 版）与下载信息。文中"（未核实）"表示仅有搜索摘要、二手来源或来源间互相矛盾。笔记之间的分歧及处理见"许可证与活跃度"一节末尾。

## 灵策智算改自 LobsterAI，StaffDeck 最像企业版

**结论先行：灵策智算桌面端运行在 OpenClaw 上，并改自 LobsterAI；企业数字员工最近邻是 StaffDeck，功能覆盖最广的是 OpenClaw 与 DeerFlow 2.0，国产替补是 QwenPaw 与 CowAgent。** 判断的基线来自灵策智算官网：它把产品定义为企业级"AI 数字员工"，桌面客户端在本地执行任务并"可直出 PPT、Word、Excel"，手机与电脑"双端互联，一句话即可远程操作电脑"，宣称 **100+ 内置 Skills**、长时记忆、定时任务、多模型自由切换，以及目录边界授权、工具调用审批、操作可回溯和关键动作确认 ([官网首页](https://ai.lynxce.cn/))。产品页进一步描述了 Main Agent 调度 Topic Agent 的工作台、"学习笔记→候选 Skill→正式 Skill→全局 Skill"的四级技能进化、"用户身份与偏好/项目背景与约束/任务上下文"三层记忆、团队知识库/Skill 库/上下文库与按角色分级权限和全链路审计、飞书/企微/钉钉预置连接器，以及岗位化数字员工、一句话生成的"轻系统"和启用前可试跑的自动化任务 ([工作台](https://ai.lynxce.cn/product-workspace.html); [技能与记忆](https://ai.lynxce.cn/product-memory.html); [团队协作](https://ai.lynxce.cn/product-collaboration.html); [企业级个性化](https://ai.lynxce.cn/product-personalization.html))。企业版按年约定制，部署方式可选公有云多租户或私有化独立部署，覆盖本地机房、专有云 VPC 与混合架构 ([定价](https://ai.lynxce.cn/pricing.html); [企业合作](https://ai.lynxce.cn/enterprise-cooperation.html))。有四个背景细节影响比较口径：工作台页面同时写着"7×24 云端持续运行、离线不中断"，说明它实际是本地客户端加云端执行的混合形态；官网文案仍称桌面客户端为邀请制内测，并自承 macOS 版未签名，但下载接口已列出 Windows 2.1.9（2026-10-04）、macOS Apple Silicon 2.0.6、macOS Intel 1.5.7、iOS 1.1.0（App Store）与 Android 1.2.3 的安装包，首页的"敬请期待"只是脚本加载前的占位，手机端 2026-10-02 起可把任务交给"云端或你自己的电脑"执行 ([官网·更新日志](https://ai.lynxce.cn/changelog.html))；客户案例全部匿名（"某电商运营团队"等），效率数字属厂商口径；营销页面没有提到代码仓库，但更新日志直接写出了 OpenClaw 与 DeepSeek Harness 两套底层引擎（详见下段）。同期国内已有一批基于 OpenClaw 封装的闭源"龙虾"产品，如腾讯 QClaw 与 WorkBuddy、智谱 AutoClaw ([IT之家](https://www.ithome.com/0/927/143.htm); [IT之家](https://www.ithome.com/0/927/230.htm); [界面新闻](https://www.jiemian.com/article/14095547.html))，灵策智算同属这一波，但下文只比较真正开源的项目。

**LobsterAI 不只是最像，而且就是灵策智算桌面端的上游。** 网易有道 2026-02-11 推出、02-19 宣布开源 ([京报网](https://news.bjd.com.cn/2026/03/18/11637393.shtml))，量子位报道其定位为"7×24 小时全场景个人助理 Agent" ([量子位](https://www.qbitai.com/2026/02/378453.html))，与灵策智算页脚的"一个 7×24 小时帮你干活的全场景个人助理 Agent"几乎相同。更硬的证据来自灵策智算自己的更新日志：它把对话模式称为"Cowork"，2.0.7 版写到"两套 Harness"并"改善飞书、云信和 Bee 插件的新版引擎兼容性"，2.1.0 版修复"SQLite 启动失败" ([官网·更新日志](https://ai.lynxce.cn/changelog.html))。这些都能在 LobsterAI 仓库里找到原型：README 写明"Cowork 是 LobsterAI 的产品与会话层，OpenClaw 是底层运行时和网关"，另设 DeepSeek Harness（dsh）作为第二引擎，会话数据存于本地 SQLite；package.json 锁定的 OpenClaw 插件里正好有 openclaw-lark（飞书）、openclaw-nim-channel（网易云信）与 openclaw-netease-bee（网易小蜜蜂） ([README_zh](https://raw.githubusercontent.com/netease-youdao/LobsterAI/main/README_zh.md); [package.json](https://raw.githubusercontent.com/netease-youdao/LobsterAI/main/package.json))。网易云信与网易小蜜蜂是网易自家的通讯产品，出现在一家福建公司的插件列表里，很难用巧合解释。灵策智算官网与更新日志都没有提到 LobsterAI，但安装包把它坐实了。2026-10-05 在一台装有 macOS 2.0.6 版的电脑上核对：包内 package.json 的名称是 lynxceai，带有与 LobsterAI 结构相同的 openclaw 配置段，锁定 OpenClaw v2026.6.1；插件清单的顺序，以及企微、微信、网易云信、网易小蜜蜂等插件的版本号，都与 LobsterAI 相同。资源目录里的 keyfrom、tray、app-icon、SKILLs 与 LobsterAI 打包配置同名，OpenClaw 运行时也放在 LobsterAI 专用的 cfmind 目录下；另有 deepseek-harness-runtime、lynxce-harness-runtime、browser-extension 与 enterprise 四个新增目录。客户端内核为 Electron 40.2.1，界面代码不在安装包内，而是从用户目录下的 renderer-updates 热更新目录加载。结合它锁定的 OpenClaw 版本和更新日志首条记录的日期推断，它大约在 2026 年 6 月从 LobsterAI 分出。它是否在应用内保留了 LobsterAI 的 MIT 版权声明，尚未核实。仓库自述为"desktop-grade AI agent… data analysis, slides, docs, video & web research… takes commands from your phone via WeChat, Feishu, DingTalk & Telegram" ([GitHub](https://github.com/netease-youdao/LobsterAI))；README 描述了 Electron 43 + React 18 的 macOS/Windows 客户端、28 个可配置技能（Word/Excel/PPT/PDF/Remotion 视频/浏览器自动化等）、用自然语言或界面创建的定时任务、本地 SQLite 加 MEMORY.md/USER.md/SOUL.md 的记忆，以及对文件、终端、网络等敏感操作的审批门 ([README_zh](https://raw.githubusercontent.com/netease-youdao/LobsterAI/main/README_zh.md))。由于底层就是 OpenClaw，它理论上继承 OpenClaw 的技能市场与自动化能力，但 README 未说明其中哪些在界面里暴露。它的短板恰好是灵策智算在其上加做的部分：没有团队、权限、审计和企业版，没有云端执行，也没有原生手机 App。

**OpenClaw 是这一代产品的公共底座和功能上限。** 它由独立的 501(c)(3) 基金会托管，"没有付费层、托管服务或代币" ([README](https://raw.githubusercontent.com/openclaw/openclaw/main/README.md); [The New Stack](https://thenewstack.io/openclaw-foundation-nonprofit-status/))，2026 年 3 月一度成为 GitHub 星标最多的仓库 ([Wikipedia](https://en.wikipedia.org/wiki/OpenClaw))；网关守护进程之外有 macOS/iOS/Android/Windows/Linux 伴侣 App、ClawHub 技能注册表、会起草技能提案的 Skill Workshop、带试跑的 Automations、五档 exec 审批和带后台整理的三层记忆（细节见下一节）。它的问题同样清楚：安全文档写明"一个网关一个信任边界"，只适合单个操作者或彼此信任的团队 ([security](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/gateway/security/index.md))；改名期间曾披露零点击 WebSocket 劫持漏洞 CVE-2026-25253 ([eastondev](https://eastondev.com/blog/en/posts/ai/20260204-openclaw-rename-history/))，ClawHub 出现过传播恶意软件的技能 ([TechRadar](https://www.techradar.com/pro/moltbot-is-now-openclaw-but-watch-out-malicious-skills-are-still-trying-to-trick-victims-into-spreading-malware))，国家互联网应急中心 2026-03-10 发布风险提示 ([新华网](https://www.news.cn/tech/20260310/959f13d18edb4759ae031a5e30523d23/c.html))——这正是灵策智算"安全是架构，不是附加项"话术瞄准的空档。

**四个替补各有所长。** QwenPaw（原 CoPaw，阿里通义实验室 2026 年 2 月开源、4 月更名）提供 Tauri 桌面 Beta（Windows 10+/macOS 14+）、钉钉/飞书/微信/QQ 等通道、"实时上下文/完整对话历史/ReMe 自进化知识库"三层记忆、内核沙箱 + Tool Guard + File Guard + Skill Scanner + allow/deny/ask 的五层防护、cron 与技能/插件市场，还内置无需 API Key 的 QwenPaw-Flash 本地模型 ([README](https://raw.githubusercontent.com/agentscope-ai/QwenPaw/main/README.md); [README_zh](https://raw.githubusercontent.com/agentscope-ai/QwenPaw/main/README_zh.md); [IT之家](https://www.ithome.com/0/938/334.htm))。CowAgent（原 chatgpt-on-wechat）有 macOS/Windows 桌面客户端，国内通道覆盖最全（微信、飞书、钉钉、企业微信机器人与应用、QQ、公众号等），并有 context→daily→core 三层记忆、多 Agent 团队、定时任务与 Skill Hub/ClawHub 一键装技能 ([README](https://raw.githubusercontent.com/zhayujie/chatgpt-on-wechat/master/README.md))，但笔记中未见审批与审计机制。Hermes Agent 的技能自进化最成熟，网关已覆盖钉钉、飞书与企业微信 ([Hermes Docs](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/); [PR #3847](https://github.com/NousResearch/hermes-agent/pull/3847))，Hermes Desktop 2026-06 起公测 ([Decrypt](https://decrypt.co/369952/hermes-ai-agent-official-app-terminal))，还能自动导入 OpenClaw 的设置、记忆与技能 ([README](https://raw.githubusercontent.com/NousResearch/hermes-agent/main/README.md))。DeerFlow 2.0 是服务端最完整的"超级 Agent 底座"：本地/Docker/K8s 三种沙箱、含飞书/企微/钉钉在内的 8 个 IM（无需公网 IP）、cron、长期记忆、子 Agent 并行，并能产出报告、幻灯片和 Excel/Word ([README](https://raw.githubusercontent.com/bytedance/deer-flow/main/README.md))，缺的是桌面客户端和团队模型。海外的 Eigent（多 Agent workforce、定时/事件/应用三类自动化、企业版 SSO 与访问控制，但无 IM 通道）([README](https://raw.githubusercontent.com/eigent-ai/eigent/main/README.md)) 与 Andrew Ng 团队的 OpenWorker（"交付成品而非聊天"，四层治理含审计轨迹，远程入口仅 Slack）([README](https://raw.githubusercontent.com/andrewyng/openworker/main/README.md)) 可作桌面形态参照。

**企业"数字员工"一侧，StaffDeck 最像。** 它由面壁智能、东北大学—面壁联合实验室、清华 THUNLP、OpenBMB 等联合开发，2026-07-15 开源，提供 macOS/Windows/Linux 安装包；数字员工带岗位、工号与能力边界，按状态机驱动的 SOP 工作（SOP 可用自然语言生成、可视化编辑并做版本控制），配有分层知识库，可经 HTTP API、MCP 或定时任务自主执行，保留完整执行 Trace 并支持人工接管，通道为微信（iLink）与企业微信 ([README](https://raw.githubusercontent.com/OpenBMB/StaffDeck/main/README.md))；媒体称其预置财务报销、法务合规、人力服务、IT 支持、行政管理 5 个员工并支持完全私有化（未核实）([量子位](https://www.qbitai.com/2026/07/453245.html))。缺口是没有飞书/钉钉、未见 Office 交付，且 AGPL-3.0 对对外服务有源码公开义务。浙江联通的 UniEmployee（MIT）把客服、数据分析、销售、HR、BI 等 8 个示例员工做成"可审批、可观测"的数字员工，带 HITL、审计轨迹与按员工隔离的长期记忆，但 IM 通道仍在规划、仅 330 star ([README](https://raw.githubusercontent.com/zj-unicom-ai/UniEmployee/main/README.md))。Paperclip（MIT）自称"如果 OpenClaw 是员工，Paperclip 就是公司"，提供组织架构、心跳、例行任务、预算、审批门、Skill Studio 与带回滚的治理，执行则委托给 OpenClaw、Hermes、Claude Code、Codex 等 ([README](https://raw.githubusercontent.com/paperclipai/paperclip/main/README.md))。Cherry Studio 与 Eigent 也各有企业版，分别提供私有化部署加 RBAC、SSO 加访问控制 ([Cherry Studio README](https://raw.githubusercontent.com/CherryHQ/cherry-studio/main/README.md); [Eigent README](https://raw.githubusercontent.com/eigent-ai/eigent/main/README.md))，但企业版是否开源未确认，且 Cherry Studio 的 Agent 模式被评为"仍处早期" ([promptquorum](https://www.promptquorum.com/local-llms/cherry-studio-ai-desktop-client))。

**入口层的"手机遥控 + 国内 IM"已被大厂官方插件抹平。** 开源项目实现"手机一句话、电脑执行、结果回传"的主路径是本地网关加 IM 机器人，无需公网 IP。2026 年起飞书、钉钉、企业微信与微信相继为 OpenClaw 提供官方接入：飞书官方插件 larksuite/openclaw-lark 以用户 OAuth 身份读写消息、文档、多维表格、电子表格、日程与任务，并用交互卡片实时更新状态 ([README](https://raw.githubusercontent.com/larksuite/openclaw-lark/main/README.md))，正对应灵策智算"群聊 @ 发起任务、结果回写文档"；仓库自述为钉钉官方插件的 dingtalk-openclaw-connector 支持 AI Card 流式状态、钉钉文档创建/追加与待办 ([README](https://raw.githubusercontent.com/DingTalk-Real-AI/dingtalk-openclaw-connector/main/README.md))，对应"任务状态实时推送群消息"；企业微信 2026-03-08 推出长连接模式"三步接入 OpenClaw"，可收发文件 ([腾讯云开发者社区](https://cloud.tencent.com/developer/article/2637067))，腾讯另发布 MIT 许可的官方微信插件 ([GitHub](https://github.com/Tencent/openclaw-weixin))。原生手机 App 方面，OpenClaw 于 2026 年 6 月发布 iOS/Android 伴侣节点应用，可把手机摄像头、定位、通知暴露给自托管网关 ([MarkTechPost](https://www.marktechpost.com/2026/06/29/openclaw-releases-ios-and-android-companion-node-apps-that-connect-a-phone-to-a-self-hosted-ai-agent-gateway/))，exec 审批提示也会推送到这些 App ([exec-approvals](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/exec-approvals.md))；但它能否充当日常下达任务的主界面、节点 App 本身是否开源，均未核实。Open Interpreter 的 01 语音遥控项目则自 2024-11 起停更 ([GitHub](https://github.com/openinterpreter/01))。

**交付与技能层同样不再是壁垒。** "一句话产出可下载 Office 文件"在 2026 年主要靠"通用 Agent + 文件技能"拼装：OfficeCLI（Apache-2.0）是专为 Agent 设计的 Word/Excel/PowerPoint 单二进制工具，内置 MCP、350+ Excel 函数求值与模板合并 ([README](https://raw.githubusercontent.com/iOfficeAI/OfficeCLI/main/README.md))；ppt-master（MIT）以 Skill 形式导出原生可编辑 PPTX ([README](https://raw.githubusercontent.com/hugohe3/ppt-master/main/README.md))；MoneyPrinterTurbo（MIT）从一个主题生成带字幕配乐的短视频 ([README](https://raw.githubusercontent.com/harry0703/MoneyPrinterTurbo/main/README.md))；DB-GPT（MIT）覆盖 Text-to-SQL 与生成式 BI 看板，可对标灵策智算的数据分析数字员工 ([README](https://raw.githubusercontent.com/eosphoros-ai/DB-GPT/main/README.md))。要避开的是 Anthropic 官方仓库里的 docx/pptx/xlsx 技能，它们明确是"source-available, not open source" ([README](https://raw.githubusercontent.com/anthropics/skills/main/README.md))。技能格式上，Anthropic 2025 年 12 月开放 SKILL.md 规范后，到 2026 年 3 月已有 32 个工具采用 ([Simon Willison](https://simonwillison.net/2025/Dec/19/agent-skills/); [agentman](https://agentman.ai/blog/agent-skills-ecosystem-report-2026))，社区列表 awesome-openclaw-skills 自称收录 5,400+ 技能 ([GitHub](https://github.com/VoltAgent/awesome-openclaw-skills))，"100+ 内置 Skills"只是起步线。技能自进化是开源追得最快的一项：OpenClaw Skill Workshop 让 Agent 把可复用的工作起草成待审提案，记录扫描状态、哈希与回滚元数据，提供 off/propose/auto 三档自学习和每周技能库复盘 ([configuration.md](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/skill-workshop/configuration.md); [how-it-works.md](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/skill-workshop/how-it-works.md))，与灵策智算"学习笔记→候选→正式→全局、每步可确认"的路径几乎同构；Hermes 的 `/learn` 能把"刚才在对话里走过的流程"直接生成 SKILL.md ([skills.md](https://raw.githubusercontent.com/NousResearch/hermes-agent/main/website/docs/user-guide/features/skills.md))；港大 HKUDS 的 OpenSpace（MIT）以 FIX/DERIVED/CAPTURED 三类更新，在 Claude Code、Codex、OpenClaw、Hermes 之间共享和演化技能 ([README](https://raw.githubusercontent.com/HKUDS/OpenSpace/main/README.md))。不过这些实现仍不成熟——OpenClaw 有"界面显示已应用、实际未写入 SKILL.md"的缺陷报告 ([issue #131330](https://github.com/openclaw/openclaw/issues/131330))——而且研究发现，在 25 种 Agent 与方法的组合中，全部 21 种经过进化的配置都写出了不安全的产物 ([arXiv 2608.12851](https://arxiv.org/abs/2608.12851))，"提案 + 人审"比全自动更适合企业。

**记忆层的差距只剩交互细节。** 灵策智算的三层记忆、按项目隔离、记忆面板可查可改可删，在开源里有多种对应：OpenClaw 用 USER.md、MEMORY.md 与每日笔记分层，并由默认开启的 dreaming 在后台分 light→REM→deep 三个阶段把日常材料提炼进长期记忆，同时产出可供审查的 DREAMS.md ([memory.md](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/memory.md); [dreaming.md](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/dreaming.md))；QwenPaw 与 CowAgent 都直接以"三层记忆"命名；Agent Zero 的 Projects 按项目隔离文件、指令、密钥与记忆 ([README](https://raw.githubusercontent.com/agent0ai/agent-zero/main/README.md))。独立记忆层里，Mem0（Apache-2.0）由 LLM 决定 ADD/UPDATE/DELETE/NOOP ([论文页](https://www.emergentmind.com/papers/2504.19413))，Graphiti（Apache-2.0）给事实设有效期、旧事实失效而非删除 ([README](https://raw.githubusercontent.com/getzep/graphiti/main/README.md))，上海记忆张量的 MemOS（Apache-2.0）提供 OpenClaw 与 Hermes 插件，并自报接入后 OpenClaw 任务完成率从 36.63% 升至 50.87%（厂商数据，无第三方复现）([README](https://raw.githubusercontent.com/MemTensor/MemOS/main/README.md))。差别在于这些开源件的冲突消解是自动的；笔记中未见哪家像灵策智算那样，在新旧记忆冲突时把决定交给用户确认。

**自动化层的"启用前试跑"开源已有，"文件变更触发"仍要自己拼。** OpenClaw 的 Automations 支持五种调度（含命令退出即触发的 on-exit 与按命令输出行触发的 stream）、可调用 MCP 工具的条件监视脚本、webhook 与 Gmail PubSub 触发，以及周期性 heartbeat ([schedules.md](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/automation/cron-jobs/schedules.md))；它会从对话中识别重复请求、提议转成自动化，**试跑是"真实运行、真实投递"，批准的就是计划将来会产出的结果**，运行失败计入错误并通知，反复出错则自动停用 ([how-it-works.md](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/automation/cron-jobs/how-it-works.md))——与灵策智算"启用前试跑、失败通知"基本一致。DeerFlow 的定时任务可设目标评估，多次失败后自动暂停 ([README_zh](https://raw.githubusercontent.com/bytedance/deer-flow/main/README_zh.md))；Eigent 区分 Scheduled/Event/App 三类自动化；Dify 的 Trigger 则只对 Workflow 应用生效 ([Dify Docs](https://docs.dify.ai/zh/cloud/use-dify/nodes/trigger/schedule-trigger))。没有项目把"文件变更"做成一等触发器，需要用 OpenClaw 的 stream 调度挂一个文件监听命令（例如基于 [watchdog](https://github.com/gorakhargosh/watchdog)）；灵策智算 FAQ 里"从最近节点继续执行"的能力，则要引入 Temporal（MIT）这类持久化执行引擎 ([GitHub](https://github.com/temporalio/temporal))。多模型切换已彻底商品化：LiteLLM（MIT，`enterprise/` 目录除外）可接入 100+ 提供方 ([LICENSE](https://raw.githubusercontent.com/BerriAI/litellm/main/LICENSE))，OpenClaw 自带主备模型与模型白名单 ([models.md](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/models.md))。

**治理层是唯一真正的空白，而且空得有原因。** 审批与沙箱几乎人人都有：OpenClaw 提供 deny/allowlist/ask/auto/full 五档 exec 策略、按 Agent 的 allowlist 与可逐条撤销的常设授权，但沙箱默认关闭 ([exec-approvals](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/exec-approvals.md); [sandboxing](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/gateway/sandboxing.md))；QwenPaw 叠加五层防护；OpenWorker 设有"不可逆操作永远需人工"的硬底线与审计轨迹 ([README](https://raw.githubusercontent.com/andrewyng/openworker/main/README.md))；Agent Zero 的 Time Travel 能对工作区快照做 diff 与回滚 ([README](https://raw.githubusercontent.com/agent0ai/agent-zero/main/README.md))。缺的是把团队、权限、审计和 Agent 运行时绑在一起。OpenClaw 文档明言一个网关只对应一个信任边界；有 RBAC 的平台则多把它留给付费版：Dify 社区版只有单一工作空间、没有 SSO 与审计日志 ([阿里云](https://help.aliyun.com/zh/dms/introduction-to-dify-enterprise-edition))，n8n 与 Flowise 的 SSO、审计都在企业版 ([codimite](https://codimite.ai/n8n/n8n-community-vs-enterprise/); [Flowise Docs](https://docs.flowiseai.com/using-flowise/workspaces))，FastGPT 的团队权限与 MaxKB 的多租户、操作日志也属商业版（厂商文档被拦截，未直接核实）([OSCHINA](https://www.oschina.net/news/343279/maxkb-1-10-3-lts))。开源部分自带 RBAC、用户组与 SSO/LDAP 的，主要是 Bisheng（Apache-2.0）([README_CN](https://raw.githubusercontent.com/dataelement/bisheng/main/README_CN.md)) 和 Open WebUI（带品牌条款；社区版是否全部免费，厂商页与第三方说法矛盾，未核实）([Docs](https://docs.openwebui.com/enterprise/security/))，而两者都不是本地执行型 Agent。"轻系统"同理：NocoBase 内置 AI 员工，2026-02 把许可证基底从 AGPL 改为 Apache-2.0 ([博客](https://www.nocobase.com/en/blog/weekly-updates-20260226))；Teable 的 AI Database Agent 能生成带登录与自定义域名的应用（厂商博客，社区版可用性未核实）([teable.ai](https://teable.ai/blog/best-no-code-ai-app-builders))；但两者与 Agent 运行时之间只能经 MCP/API 粘合，Dyad 一类代码生成器又缺少数据层与权限层。

## 三套组合最多补齐八成功能，身份与审计仍需自研

开源界的现实做法是拼装。下面三套方案只选用有文档证据能互相对接的组件：MemOS 提供 OpenClaw 与 Hermes 插件 ([README](https://raw.githubusercontent.com/MemTensor/MemOS/main/README.md))，Paperclip 自带 OpenClaw 与 Hermes 适配器 ([README](https://raw.githubusercontent.com/paperclipai/paperclip/main/README.md))，LangBot 可把企微/飞书/钉钉消息路由到 Dify、Coze、OpenClaw、Hermes 与 DeerFlow ([GitHub](https://github.com/langbot-app/LangBot))，DeerFlow 原生支持 LangSmith/Langfuse 追踪 ([README](https://raw.githubusercontent.com/bytedance/deer-flow/main/README.md))。覆盖分沿用上一节的 16 项口径。

| 方案 | 组成（许可证） | 覆盖（满分 16） | 主要缺口与自研量 |
|---|---|---|---|
| A 个人工作台平替 | OpenClaw（MIT）运行时；LobsterAI（MIT）或 AionUi（Apache-2.0）/ClawX（MIT）作桌面外壳；飞书、钉钉、微信官方插件（MIT）与企业微信长连接；MemOS 插件（Apache-2.0）；OfficeCLI（Apache-2.0）/ppt-master（MIT） | 约 12：桌面、IM 遥控与文档回写、ClawHub + Skill Workshop、三层记忆 + dreaming、定时 + 试跑 + 事件触发、分级审批、多模型 | 无团队与 RBAC，审计停留在配置层，无轻系统和企微侧边栏；需手动打开默认关闭的沙箱并管住技能来源 |
| B 企业数字员工中台 | Paperclip（MIT）负责组织、心跳、预算、审批与 Skill Studio；OpenClaw/Hermes（MIT）执行；Bisheng（Apache-2.0）提供知识库与 RBAC/SSO；LiteLLM（MIT 核心）路由模型；Langfuse（MIT 核心）追踪；NocoBase（Apache-2.0 + 补充条款）做轻系统 | 约 13.5：在 A 的执行能力之上增加岗位与组织架构、例行任务、预算与审批门、技能版本回滚、知识库权限、模型路由 | 四套系统的身份、权限与日志各自为政，需自研 SSO 贯通和统一的 OTel 审计管道；OpenClaw 单信任边界要求按团队拆网关；运营看板与上下文库共享需自建 |
| C 服务端私有化 | DeerFlow 2.0（MIT）+ LiteLLM + Langfuse + Teable（AGPL 核心）或 NocoBase | 约 11.5：K8s 沙箱、8 个 IM（含飞书/企微/钉钉）、子 Agent 长任务、Office 交付、cron、原生追踪 | 无本机桌面执行，放弃"数据留在员工电脑"；无技能自进化与团队 RBAC；Teable 的 AGPL 对外提供服务时须公开衍生代码 |

三套方案的取舍很清楚。方案 A 最快可用，但必须按国家互联网应急中心的提示管住插件来源、禁用自动更新 ([腾讯新闻](https://news.qq.com/rain/a/20260310A0753G00))，并把 Skill Workshop 设为 propose 模式；飞书官方插件以用户 OAuth 身份行事，权限边界等于个人权限，企业的分级管控仍得在平台层做 ([README](https://raw.githubusercontent.com/larksuite/openclaw-lark/main/README.md))。方案 B 覆盖最全，却要把 Paperclip、Bisheng、NocoBase 与 OpenClaw 四套账号体系打通，才能接近灵策智算宣称的"按用户、身份与角色组控制项目级资源 + 全链路审计"；OpenClaw 本身不输出完整的操作审计，追踪需要自行埋点。方案 C 适合有 K8s 运维能力、只需服务端执行的组织。若目标是像灵策智算那样提供公有云多租户服务，方案 B 里的 NocoBase 需要换掉（其补充条款禁止对外提供低代码/AI 平台类 SaaS），Teable 与 new-api 的 AGPL 也会带来源码公开义务。

## 开源仍未覆盖的差异集中在组织治理与移动端

把能拼的都拼上之后，剩下的差异集中在"组织"而不是"智能"上。下表左侧取自灵策智算官网的表述 ([工作台](https://ai.lynxce.cn/product-workspace.html); [技能与记忆](https://ai.lynxce.cn/product-memory.html); [团队协作](https://ai.lynxce.cn/product-collaboration.html); [企业级个性化](https://ai.lynxce.cn/product-personalization.html); [企业合作](https://ai.lynxce.cn/enterprise-cooperation.html))，右侧是笔记中找到的最接近的开源实现。

| 差异点 | 灵策智算官网表述 | 开源最接近的实现 | 判断 |
|---|---|---|---|
| 团队治理闭环 | 知识库、Skill 库、上下文库作为团队资产共享；按用户、身份与角色组控制项目级资源；按风险等级配置确认策略；全链路审计；任务可回退到任意历史节点；Skill 调用、任务完成率、活跃成员看板 | Bisheng 与 Open WebUI 的 RBAC/SSO，Langfuse 追踪，Agent Zero Time Travel，Paperclip 审批与回滚，StaffDeck 执行 Trace | 只有零件，没有一体化产品；最大空白 |
| 原生手机控制台 | iPhone/Android App 可对话、出图、出视频，并一句话远程操作电脑 | OpenClaw 节点 App（偏设备能力与审批，是否开源未核实）；其余项目都走 IM | 部分空白 |
| 企业微信深度动作 | 会话侧边栏调用；文件同步到企微文件库 | 企微长连接收发文件；写入智能表格（来源页被拦截，未核实） | 空白 |
| 跨员工技能泛化 | 四级进化，"一次纠正全局泛化" | OpenClaw Skill Workshop 提案制、Hermes `/learn`、OpenSpace 共享技能层、Paperclip 组织级技能库 | 机制已有，"自动跨员工泛化"没有一手证据 |
| 轻系统嵌入执行流 | 一句话生成看板/表单/台账，按账号与可见范围分享，可嵌入数字员工流程 | NocoBase AI 员工、Teable 应用生成，经 MCP/API 对接 | 需要自写粘合层，且有 SaaS 许可限制 |
| 岗位方案与交付服务 | 售前、项目经理、数据分析、营销、HR 五类数字员工；L1–L4 AI 转型服务；需求梳理→PoC→部署集成→验收→持续运营 | StaffDeck 预置财务、法务、人力、IT、行政 5 个员工（媒体报道，未核实）；UniEmployee 8 个示例员工 | 属商业服务层，开源不提供 |

表外还有三处较小的差异，开源能拼但没有现成产品：记忆冲突时请用户确认（开源记忆层多为自动消解）、"文件变更"作为一等触发器（需 stream 调度加文件监听）、定时任务"从最近节点继续"（需持久化执行引擎）。反过来，**灵策智算宣传的若干卖点在开源里已是标配**：100+ Skills、三层记忆、带试跑的定时任务、多模型切换、工具审批、飞书与钉钉直连、PPT/Word/Excel 直出，都不再构成差异。市场背景则解释了为什么治理和打包仍有价值：2026 年 3 月国家互联网应急中心与新华网相继就 OpenClaw 发布风险提示，多所高校要求卸载 ([腾讯新闻](https://news.qq.com/rain/a/20260310A0753G00); [安全内参](https://www.secrss.com/articles/88431))；与此同时各大云厂商推出一键部署，甚至出现"500 元上门安装 OpenClaw"的生意 ([蓝鲸财经](https://www.lanjinger.com/d/1772766680151033575))。企业要的不只是能力，而是能管得住、装得上的能力，这正是灵策智算"本地执行 + 审计 + 私有化交付"组合的市场空间。

## 许可证与活跃度：先剔除伪开源和停更项目

**许可证是比 star 更硬的筛子。** 不少项目常被称作"开源"，但带有限制商用或分发的附加条款：Dify 是修改版 Apache-2.0，未经授权不得运营多租户环境、不得移除控制台 Logo ([LICENSE](https://raw.githubusercontent.com/langgenius/dify/main/LICENSE))；FastGPT 禁止运营与其类似的多租户 SaaS ([LICENSE](https://raw.githubusercontent.com/labring/FastGPT/main/LICENSE))；NocoBase 社区版不得对外提供无代码/低代码/AI 平台类 SaaS ([LICENSE.txt](https://raw.githubusercontent.com/nocobase/nocobase/main/LICENSE.txt))；NocoDB 与 n8n 改用 Sustainable Use License，只允许内部业务与非商业使用 ([NocoDB](https://raw.githubusercontent.com/nocodb/nocodb/develop/LICENSE.md); [n8n](https://raw.githubusercontent.com/n8n-io/n8n/master/LICENSE.md))；Open WebUI 附加品牌条款 ([LICENSE](https://raw.githubusercontent.com/open-webui/open-webui/main/LICENSE))；LobeHub 分发派生作品须取得商业许可 ([LICENSE](https://raw.githubusercontent.com/lobehub/lobehub/main/LICENSE))；Suna/Kortix 当前为 Elastic License 2.0 ([LICENSE](https://raw.githubusercontent.com/kortix-ai/suna/main/LICENSE))；功能上与灵策智算几乎一一对应的 OpenWorkBuddy 采用 PolyForm Noncommercial ([README](https://raw.githubusercontent.com/CatCatUncle/openworkbuddy/main/README.md))；知道创宇 AiPy 在 GPL-3.0 之外禁止 SaaS 与商业集成 ([LICENSE](https://raw.githubusercontent.com/knownsec/aipyapp/main/LICENSE))；Anthropic 的文档类技能则只是 source-available。另一类是强 copyleft：StaffDeck、Cherry Studio、AstrBot、Teable 核心与 new-api 为 AGPL-3.0，MaxKB 为 GPL-3.0，可以商用，但对外提供网络服务或分发时须公开衍生代码。能"拿来商用封装"的干净 MIT/Apache 组合是 OpenClaw、LobsterAI、QwenPaw、CowAgent、Hermes Agent、DeerFlow、Eigent、Paperclip、Bisheng、nanobot、LangBot、OfficeCLI、ppt-master、MemOS 与 Mem0；想做灵策智算式"公有云多租户"服务，只能在这一组里选。

**核心候选几乎都在一周内有推送，但有几处放缓和停更值得避开。** Coze Studio 许可证最干净（Apache-2.0，允许多租户），却自 2026-07-29 起两个多月无提交，开源版还缺多用户与工作区隔离 ([GitHub](https://github.com/coze-dev/coze-studio); [掘金](https://juejin.cn/post/7534879121131126825))；飞书官方 OpenClaw 插件最后推送于 2026-07-22，积压 314 个未关 issue ([GitHub](https://github.com/larksuite/openclaw-lark))；京东 JoyAgent-JDGenie 自 2026-02-12 起无推送 ([GitHub](https://github.com/jd-opensource/joyagent-jdgenie))，one-api 自 2026-01-09 起无推送 ([GitHub](https://github.com/songquanpeng/one-api))，PandasAI 约 11 个月无推送，且有 SQL 注入漏洞 CVE-2026-30273 ([GitHub](https://github.com/sinaptik-ai/pandas-ai); [OpenCVE](https://app.opencve.io/cve/CVE-2026-30273))；Vanna、Open Deep Research、AgentGPT、Bytebot 已归档 ([Vanna](https://dev.to/miya_ng/vanna-aivanna-has-been-archived-since-march-whats-actually-frozen-what-isnt-and-your-four-479g); [Open Deep Research](https://github.com/langchain-ai/open_deep_research); [AgentGPT](https://github.com/reworkd/AgentGPT); [Bytebot](https://github.com/bytebot-ai/bytebot))。2026 年 star 通胀明显（OpenClaw 约 39 万、MoneyPrinterTurbo 12.8 万），判断成熟度应同时看推送频率、issue 处理，以及是否有公司或基金会背书。

## 结论

灵策智算个人版的功能清单，几乎就是 2026 年开源"龙虾"架构的共识清单：本地网关、IM 通道、SKILL.md 技能、Markdown 分层记忆、带试跑的定时任务和分级审批。这并不意外：灵策智算的更新日志表明它的桌面端就跑在 OpenClaw 与 DeepSeek Harness 上，而且直接改自 LobsterAI。个人和小团队今天就能用 LobsterAI、QwenPaw 或 CowAgent 在自己的机器上获得它的大部分体验，只需自付模型调用费用。它真正可防守的差异只剩企业治理闭环、云端执行与原生移动端、国内 IM 的最后一公里（企微侧边栏与文件库），以及岗位化方案与交付服务。这些恰好是开源 LLMOps 厂商刻意留在付费版的部分，也是 OpenClaw 基金会明确不做的部分（没有付费层，一个网关只对应一个信任边界），所以这道缺口更可能长期存在，而不是很快被社区填平。灵策智算的"四级技能进化、每步人工确认"与 OpenClaw 的提案制同构，也与技能误进化研究给出的安全建议一致；在这一点上，它跟上了开源的最佳实践，但没有领先。

对准备自建的团队，成本应按"粘合层工程量"而非"功能清单"来估：方案 B 覆盖最高，但要打通四套系统的身份和审计，并按信任边界拆分网关；许可证则决定哪条路走得通，想做公有云多租户就必须避开 Dify、FastGPT、NocoBase、NocoDB 与 n8n。接下来值得跟踪四个信号：OpenClaw 是否引入多租户与 RBAC，StaffDeck 是否补齐飞书和钉钉，Coze Studio 是否恢复更新，以及企业对技能自进化采用"提案制"还是"全自动"。灵策智算的底层运行时问题，已由它自己的更新日志回答：它运行在 OpenClaw 上，安全性因此与上游 OpenClaw 的漏洞和恶意技能问题直接绑定。采购评估时，应要求厂商说明所用 OpenClaw、DeepSeek Harness 与 LobsterAI 的版本、安全补丁的跟进节奏，以及开源许可声明的保留情况。比如 macOS 2.0.6 版锁定的仍是 OpenClaw v2026.6.1，而 npm 上的最新版已是 2026.9.8；界面代码走热更新目录下发，也意味着界面层的改动不经过安装包更新。
